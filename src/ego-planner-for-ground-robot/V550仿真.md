# V550_mec + 单线二维雷达仿真

这份说明对应你的小车配置：**V550_mec 麦克纳姆轮底盘 + 单线二维雷达**。
使用厂家 V550_mec 的 STL 外观模型，在工程已有的 CMU 室内地图里运行 EGO-Planner 和 MPC。
入口是 `ego_ground_sim/launch/sim_v550_mec_2d.launch.py`。

想用空旷场地、自己摆障碍物，请看 [V550 自定义地图与轨迹显示](V550自定义地图.md)，
启动入口为 `ros2 launch ego_ground_sim sim_v550_custom.launch.py`。
现在 Gazebo 默认俯视，RViz 用绿色显示实际 B 样条规划曲线、橙色显示小车已走过的轨迹。
新增的 24 × 18 米六房间场地、门和蓝色激光显示见 [V550 大型室内仿真](V550室内仿真.md)。
该文也记录了后续撞障修正和带车身几何检查的走廊、穿门验证；下文旧测试结果仅对应当时配置。

## 1. 先启动看效果

当前开发电脑已完成编译。在终端执行：

```bash
cd ~/ego_ground_ws
source /opt/ros/humble/setup.bash
source install/local_setup.bash
export ROS_DOMAIN_ID=218
export ROS_LOCALHOST_ONLY=1
export GAZEBO_MASTER_URI=http://127.0.0.1:11358
ros2 launch ego_ground_sim sim_v550_mec_2d.launch.py
```

这三个环境变量用于让本次仿真单独通信；后续发送目标和检查话题的终端也要设置相同的值。
如果仿真窗口已经打开，直接使用它，不要重复启动同一个 Gazebo 服务。
结束时在启动终端按 `Ctrl+C`，会一起关闭本次启动的节点。

启动后会打开两个窗口：

- **Gazebo**：三维场景和厂家 V550 外观模型，启动后相机会从小车初始位置上方俯视。
- **RViz**：小车、二维障碍地图、障碍点云和规划轨迹，用来发送目标、观察规划过程。

默认起点在室内走廊的可通行位置，世界坐标约为 `(-31.3, -23.4)`，朝向 Y 轴负方向。
这些数值来自 CMU 地图的世界坐标，不表示小车离出生点有三十多米。

## 2. 让小车走起来

在 **RViz** 顶部点击 **2D Goal Pose**，在走廊空白区域按下鼠标并拖动，再松开。
先选择离小车 1～2 米的位置，观察轨迹和运动。

也可以在第二个终端准确发送一个已验证的近处目标：

```bash
cd ~/ego_ground_ws
source /opt/ros/humble/setup.bash
source install/local_setup.bash
export ROS_DOMAIN_ID=218
export ROS_LOCALHOST_ONLY=1
export GAZEBO_MASTER_URI=http://127.0.0.1:11358
ros2 topic pub --once /goal_pose geometry_msgs/msg/PoseStamped \
  '{header: {frame_id: odom_combined}, pose: {position: {x: -31.3, y: -25.4, z: 0.0}, orientation: {w: 1.0}}}'
```

这个目标沿走廊向前约 2 米。到达后再发送相同目标，小车会保持在目标附近；
如需返回，可以把目标改为 `x: -31.3, y: -23.4`。
初次测试不要把目标设在墙、障碍物或尚未观察清楚的房间里。

## 3. 仿真内部的连接

```text
Gazebo V550 + 二维激光 → /scan → sensor_bridge → /ego/obstacles → 局部地图
                                                             ↓
RViz /goal_pose → sensor_bridge → /ego/goal → EGO-Planner → B样条轨迹
                                                             ↓
Gazebo /odom_combined ───────────────────────────────────────→ MPC
                                                             ↓
                              /v550_sim/cmd_vel_raw → 看门狗 → /v550_sim/cmd_vel
                                                                            ↓
                                                                  Gazebo 平面运动插件
```

| 内容 | 本次配置 |
| --- | --- |
| 车型外观 | 厂家 `V550_mec_robot.urdf` 对应的原始 STL 模型 |
| 雷达 | 单层、720 个采样方向、10 Hz，话题 `/scan` |
| 雷达坐标系 | `laser_link` |
| 规划/里程计坐标系 | `odom_combined` |
| 车体坐标系 | `base_footprint` |
| 仿真速度限制 | 前后速度 0.35 m/s，偏航角速度 0.8 rad/s |
| 横向速度 | `linear.y=0`，当前 MPC 使用前进和转向跟踪 |
| 地面分割 | 不运行 Patchwork；单线二维扫描直接转换成障碍点 |
| 时间 | 节点统一使用 Gazebo `/clock` |

本次没有启动厂家串口驱动，也不会向实车的 `/cmd_vel` 发布控制指令。
仿真入口不需要调用实车的启用行驶服务；发送目标就会开始规划、运动。

**运动模型采用 Gazebo 的理想平面速度插件。** 它适合先验证雷达、坐标系、规划和控制接口；
还没有模拟麦轮滚子的接触、打滑、电机响应和真实轮速控制。模型中的车轮保留厂家外观和关节，
本次没有实现随平面速度联动的麦轮滚动动画，因此不能用轮子是否转动来判断控制是否生效。
仿真里的安装位置、惯量和简化碰撞体也不能代替实车标定。
二维激光只能观察扫描高度附近的障碍，扫描面上下的悬空物体、低矮障碍和台阶需要额外感知。

## 4. 改过哪些文件

| 文件 | 用途 |
| --- | --- |
| [sim_v550_mec_2d.launch.py](ego_ground_sim/launch/sim_v550_mec_2d.launch.py) | 一起启动 Gazebo、V550、雷达接口、规划、MPC 和 RViz |
| [v550_mec_sim.urdf](ego_ground_sim/urdf/v550_mec_sim.urdf) | 厂家外观、简化碰撞体、二维激光与仿真插件 |
| [meshes/v550_mec](ego_ground_sim/meshes/v550_mec) | 从你提供的厂家源码复制的原始 STL |
| [v550_cmu_indoor.world](ego_ground_sim/worlds/v550_cmu_indoor.world) | CMU 室内地图、物理和默认视角 |
| [ego_planner_v550_sim.yaml](ego_ground_sim/config/ego_planner_v550_sim.yaml) | 地图、规划、MPC 的仿真参数 |
| [v550_sim.rviz](ego_ground_sim/config/v550_sim.rviz) | RViz 模型、坐标系、地图和轨迹显示 |
| [focus_v550.py](ego_ground_sim/scripts/focus_v550.py) | 启动后设置俯视或跟随相机 |
| [trajectory_visualizer.cpp](ego_ground_sim/src/trajectory_visualizer.cpp) | 显示实际 B 样条曲线和里程计轨迹 |
| [v550_sim_check.py](ego_ground_sim/scripts/v550_sim_check.py) | 发送近处目标并记录闭环运行结果 |

改起点时优先通过启动参数覆盖，例如：

```bash
ros2 launch ego_ground_sim sim_v550_mec_2d.launch.py \
  spawn_x:=-31.3 spawn_y:=-23.4 spawn_yaw:=-1.57079632679
```

不要随意把起点改成 `(0, 0)`，它可能位于墙体或地图外。
仿真环境已有 `world`、`gui`、`rviz` 和 `focus_robot` 参数；
`gui:=false rviz:=false` 可以只启动后台，`focus_robot:=false` 可以关闭启动时的自动相机调整。

## 5. 从源码重新编译

这套入口面向当前 Ubuntu 22.04 / ROS 2 Humble / Gazebo Classic 11 环境。
如果已经在当前电脑上启动成功，可以跳过本节；以后修改 launch、URDF 或 YAML 后，要重新安装到 `install` 再启动。

缺少仿真依赖时：

```bash
sudo apt update
sudo apt install ros-humble-gazebo-ros-pkgs ros-humble-robot-state-publisher \
  ros-humble-rviz2 python3-colcon-common-extensions python3-rosdep
```

首次使用 rosdep，需要先初始化；如果已经初始化就跳过 `sudo rosdep init`。

```bash
source /opt/ros/humble/setup.bash
cd ~/ego_ground_ws
rosdep update
rosdep install --from-paths \
  src/ego-planner-for-ground-robot/ego-planner/planner \
  src/ego-planner-for-ground-robot/ego-planner/patchwork \
  src/ego-planner-for-ground-robot/ego_wheeltec \
  src/ego-planner-for-ground-robot/ego_ground_sim --ignore-src -r -y
colcon build --packages-up-to ego_ground_sim --parallel-workers 2 \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/local_setup.bash
```

## 6. 自动检查与本次结果

先启动仿真，再在已加载环境、设置相同 ROS 域的第二个终端执行：

```bash
python3 install/ego_ground_sim/share/ego_ground_sim/scripts/v550_sim_check.py \
  --goal-x -31.3 --goal-y -25.4 --report dist/v550_sim_check.json
```

脚本只发送目标，不直接发布速度。它会检查是否收到了 V550 描述、雷达、里程计和地图，并记录规划与到达结果。
应从默认起点运行；如果小车已经在目标处，可重启仿真再检查。

2026-10-15 修复轨迹显示和 MPC 跟踪后，在专用绕障场地完成的检查：

| 检查项 | 结果 |
| --- | --- |
| 起点 → 目标 | `(-2, 0)` → `(2, 0)` |
| 起终点直线距离 | 4 m |
| 实际行驶距离 | 约 5.13 m，绕过中央箱子 |
| 最终停车位置误差 | 约 0.023 m |
| 与当时有效局部曲线的采样点距离 | 均方根约 0.129 m，最大约 0.373 m |
| 收到 B 样条轨迹 | 10 条 |
| 机器人中心到测试箱子的最小距离 | 约 0.463 m |
| 二维雷达 | 每帧 720 个采样 |
| 结束速度指令 | 前后、横向、角速度均为 0 |

报告为工作空间 `dist/v550_detour_isolated_check.json`，曲线对照图为
`dist/v550_detour_tracking.png`。受重规划和跟踪误差影响，实际路径仍不会和参考曲线完全重合；
这次结果只验证该静态场地，不代表任意地图或实车精度。

该场地文件是 `ego_ground_sim/worlds/v550_detour.world`。本机可重新启动并检查：

```bash
ros2 launch ego_ground_sim sim_v550_custom.launch.py \
  world:=$HOME/ego_ground_ws/src/ego-planner-for-ground-robot/ego_ground_sim/worlds/v550_detour.world \
  spawn_x:=-2.0
```

第二个已加载环境、设置相同 ROS 域的终端：

```bash
python3 install/ego_ground_sim/share/ego_ground_sim/scripts/v550_sim_check.py \
  --goal-x 2 --goal-y 0 --report dist/v550_detour_check.json \
  --trace dist/v550_detour_paths.json
```

脚本会等待车到达目标附近并稳定停下。运行自动检查时不要同时在 RViz 发送其他目标。
早期的 `v550_sim_check.json` 和 `v550_sim_check_gui.json` 是修改前的历史报告。

## 7. 看不到模型或小车不动时

- **Gazebo 视角被墙挡住**：在左侧 World → Models 找到 `v550_mec`，双击定位；
  也可以在启动环境里运行 `python3 install/ego_ground_sim/share/ego_ground_sim/scripts/focus_v550.py` 重新调整视角。
- **RViz 看不到小车**：固定坐标系应为 `odom_combined`，RobotModel 使用 `/robot_description`；
  雷达传感器坐标系为 `laser_link`，不是原仿真的 `lidar_link`。
- **有界面但小车不动**：确认 Gazebo 没有暂停，目标不是当前位置，目标位于可通行走廊；
  查看 `/scan`、`/odom_combined`、`/planning/bspline` 和 `/v550_sim/cmd_vel`。
- **第二个终端查不到话题**：核对 `ROS_DOMAIN_ID=218`、`ROS_LOCALHOST_ONLY=1`，并加载同一工作空间环境。
- **提示模型已经存在或端口冲突**：先结束自己之前启动的这一套仿真，再重新启动。

上车步骤另见 [V550 实车部署](V550实车部署.md)。此前准备的实车源码压缩包是较早快照，
不包含本次新增的 V550 仿真文件；要复制本次仿真，请使用当前源码目录。
