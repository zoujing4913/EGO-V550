# V550 在未知环境中：RViz 给目标，在线建图并使用 EGO 前进

适用硬件：**V550_mec 麦克纳姆轮、ROS 2 Humble、N10p USB/串口二维雷达**。
底盘 IMU 默认沿用本地厂家配置的 `stm32` 模式；若车上实际是外置 IMU，需要另配对应驱动。
当前准备和软件验证在开发电脑完成，没有连接你的真实车辆，也没有完成车体尺寸、外参和制动标定。

## 1. 现在的启动链路

```text
底盘编码器/IMU → 厂家 EKF → /odom_combined → EGO/MPC
                       ↓ TF                  ↑
N10p /scan → 在线 SLAM → /map → 未知目标引导 → 已观测空地中的局部目标
      └→ 传感器桥接 → /ego/obstacles → EGO 局部地图

RViz /goal_pose → 保存 map 坐标下的最终目标
EGO 的 B 样条 → MPC → /ego/cmd_vel_raw
                           ↓
                  实车保护、未知区停车门控
                           ↓
                        /cmd_vel → 厂家底盘驱动
```

没有预先加载 `.pgm/.yaml` 地图，SLAM 随雷达观测在线建立地图。
最终目标可以在灰色未知区域，甚至位于当前地图边界之外。
引导器对未知区域作带额外代价的路线搜索，但只把已观测空地中的短距离中间目标交给 EGO。
车辆接近观测边界时等待新扫描，发现墙壁后重新选择路线，必要时原地转向观察路线方向。
在线建图、目标引导不是替换 EGO：**平滑轨迹和速度跟踪仍由 EGO + MPC 计算，没有启动 Nav2 控制器。**

这是朝用户指定目标进行探索，不自动选择并遍历所有房间。
对复杂迷宫、封闭目标、长期没有新观测、过窄门洞，不保证一定可达；找不到满足条件的局部目标时停车并报告状态。
到达位置容差为 0.25 m，目前不执行 RViz 箭头指定的最终朝向，也不使用麦轮横移。

## 3. 首次在车载电脑安装依赖并编译

把当前整个 `ego_ground_ws/src` 复制到车上，或者使用包含本次修改的 `ego_v550_unknown_nav_20261016.tar.gz`。
压缩包顶层为 `ego_ground_ws/`，先备份车上同名旧工程，再在用户主目录解压。
不要复制开发电脑的 `build/` 和 `install/` 到 ARM 车载电脑运行。

```bash
source /opt/ros/humble/setup.bash
sudo apt update
sudo apt install python3-colcon-common-extensions python3-rosdep \
  python3-numpy python3-scipy libpcap-dev libyaml-cpp-dev libboost-thread-dev \
  ros-humble-slam-toolbox ros-humble-robot-localization \
  ros-humble-turtlesim ros-humble-nav2-msgs ros-humble-ackermann-msgs \
  ros-humble-robot-state-publisher ros-humble-joint-state-publisher ros-humble-xacro
```

若 rosdep 尚未初始化，执行一次 `sudo rosdep init`；已初始化则跳过。

```bash
rosdep update
cd ~/ego_ground_ws
rosdep install --from-paths \
  src/ego-planner-for-ground-robot/ego-planner/planner \
  src/ego-planner-for-ground-robot/ego-planner/patchwork \
  src/ego-planner-for-ground-robot/ego_wheeltec \
  src/ego-planner-for-ground-robot/wheeltec_vendor --ignore-src -r -y
colcon build --packages-up-to ego_wheeltec --parallel-workers 2 \
  --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/local_setup.bash
```

这条构建包含 15 个包，其中七个是本次所需的厂家包，不要求安装 Gazebo。
开发电脑上已完成该依赖闭包构建；因没有免密码 sudo，之前缺少的 libpcap 开发文件在本地用临时解压方式验证。
车上和常规干净构建必须按上面的命令安装系统依赖，不能依赖开发电脑 `/tmp` 中的文件。

以后每个终端只加载：

```bash
source /opt/ros/humble/setup.bash
source ~/ego_ground_ws/install/local_setup.bash
```

## 4. 上车先核对两个串口、外参和车体尺寸

```bash
ls -l /dev/wheeltec_controller /dev/wheeltec_lidar
ls -l /dev/serial/by-id/
```

默认别名沿用厂家规则；没有别名时通过启动参数指定真实设备，不要猜测哪个 ttyUSB 是底盘。
如果车上已自动启动底盘、雷达或 SLAM，先确认并停止重复程序，或者对下面入口传相应的 `start_*:=false`。

实际雷达外参在 `wheeltec_vendor/turn_on_wheeltec_robot/config/robot_model.yaml` 的
`robot_model.V550_mec.base_to_laser` 中核对，修改后重新编译安装。
雷达原点、高度、朝向与真实安装必须一致。N10p 的屏蔽角度在同包 `config/wheeltec_param.yaml` 的 `x10` 中。
无效值和被屏蔽方向不会当作已观测空地；不能通过把盲区假设成空地来解决停车。

`robot_radius` 是包含轮子和突出设备的水平外轮廓包络半径。
矩形外轮廓可按 `0.5 * sqrt(长² + 宽²)` 估算，长宽单位都是米。
入口中的 **0.30 m 是待实测的默认值，不是你的实车标定结果**。
`collision_margin` 默认 0.10 m，规划还额外保留 0.10 m 跟踪余量。
默认外层路线按约 0.50 m 的方形栅格膨胀，EGO 局部地图约 0.40 m，末端保护按 0.40 m 包络检查。
外层还会叠加 EGO 实际局部地图，避免两层对拐角通行性判断不一致。
栅格取整会使很窄的门洞不可通行；不要仅为了穿门而把包络设置得比车身小。

## 5. 一个启动文件启动整条实车链路

先选择空旷场地，用 `drive:=false` 做静止观察：

```bash
ros2 launch ego_wheeltec v550_unknown_nav.launch.py drive:=false
```

确认点云、车辆 TF 和 SLAM 地图正确后，停止观察启动，使用实车执行入口：

```bash
ros2 launch ego_wheeltec v550_unknown_nav.launch.py
```

这个入口默认启动底盘、N10p、EKF、在线 SLAM、EGO、MPC、目标引导、轨迹显示和 RViz。
默认把保护节点输出连接到 `/cmd_vel`，但保护节点**启动时仍未使能，不会因为旧目标自动行驶**。

覆盖设备路径和实测半径的示例（设备和数值换成车上真实值）：

```bash
ros2 launch ego_wheeltec v550_unknown_nav.launch.py \
  controller_port:=/dev/wheeltec_controller \
  lidar_port:=/dev/wheeltec_lidar \
  robot_radius:=0.30 collision_margin:=0.10
```

车载电脑无桌面时加 `rviz:=false`，在另一台同 ROS 域的电脑打开
`ego_wheeltec/config/v550_unknown.rviz`。跨机通信不能设置 `ROS_LOCALHOST_ONLY=1`。

## 6. 检查后，使能并在 RViz 点目标

另开终端，加载上述两个环境：

```bash
ros2 run ego_wheeltec preflight.py \
  --odom-topic /odom_combined --sensor-topic /scan --sensor-type scan

ros2 topic info /cmd_vel --verbose
ros2 topic echo /ego/navigation_state
```

`/cmd_vel` 应只有实际保护节点这个预期控制发布者；不能同时运行键盘、Nav2 控制器或旧仿真控制程序。
初始可见地图生成、输入检查通过、准备好急停后，使能：

```bash
ros2 service call /ego/set_enabled std_srvs/srv/SetBool '{data: true}'
```

然后在 RViz 用 **2D Goal Pose** 设置新目标，话题为 `/goal_pose`，固定坐标系为 `map`。
先测前方短距离已知空地，再测旁边的未知区域，最后测绕墙和过门。
灰色区域的目标会保存在 map 坐标中，中间局部目标会随观测更新；看不到安全前进位置时会等待或原地观察。

RViz 的线条含义：

- 蓝色：目标方向的参考路线，可能穿过未知区域，不能当作已经验证安全的轨迹。
- 绿色：EGO 发布的 B 样条采样曲线。
- 橙色：实际里程计行驶轨迹。

停止车辆：

```bash
ros2 service call /ego/set_enabled std_srvs/srv/SetBool '{data: false}'
```

取消保留的最终目标：

```bash
ros2 service call /ego/cancel_goal std_srvs/srv/Trigger '{}'
```

传感器、指令或目标引导心跳断流会停止并解除使能，恢复后需要重新使能并给新目标。
地图等待、暂时没有可通行路线或保护拦停时，不会强行穿过；本入口关闭膨胀区自动脱困。
软件保护不能替代下位机的失联停车和实车急停，首次测试需要核对这两项的实际效果。

## 7. 限制和排查

| 现象 | 检查 |
| --- | --- |
| 找不到 `robot_localization` | 安装 `ros-humble-robot-localization`，没有它就没有厂家融合里程计 |
| 车辆不动 | 看 `/ego/guard_state`；确认使能成功后重新给了目标 |
| `waiting for fresh SLAM map` | 检查 `/scan`、TF、SLAM 日志和 `/map` |
| `waiting for new observed free space` | 前方未获得满足包络的有效观测；核对扫描屏蔽、雷达安装和目标可达性 |
| `obstacle in stopping envelope` | 实际障碍点进入预测停车区域；核对车体包络、外参及实际位置 |
| 目标附近停住 | 位置到达容差为 0.25 m；最终朝向暂不执行 |
| `goal/map too large` 或预算超限 | 先选较近目标；当前是有限预算的目标引导，没有完整的大规模探索任务管理 |
| 接近里程计 ±40 m 后停车 | 当前 EGO 平面地图为 80×80 m，需调整规划配置和边界检查，再重新验证 |

目标引导按当前位姿和目标附近的窗口搜索，允许未知区域引导，但不承诺复杂场景的全局可达性。
二维雷达不能完整感知扫描平面以外的低矮物、悬空物和坑洞。

## 8. 软件验证工具

资源/启动展开、未知区规划边界、实车保护节点的回归测试位于 `ego_wheeltec/tests/`。
`tools/v550/unknown_nav_check.py` 使用合成雷达、合成里程计运行实际 SLAM/EGO/MPC/保护链路，
目标位于墙后的初始未知区域，输出隔离在 `/ego/cmd_vel_checked`，不启动厂家串口驱动。
它要求独立 `ROS_DOMAIN_ID=225` 和 `ROS_LOCALHOST_ONLY=1`，只用于开发电脑软件检查，不是上车启动方式。
最终验证结果记录在工作空间 `dist/`；软件通过不代表已经完成真实车辆验收。

本次软件验证：实车依赖闭包 **15 个包编译通过**；地图/资源/启动展开测试 **14 项通过**；
保护节点集成测试 **2 项通过**。合成场景中最终目标 `(3, 0)` 初始处于墙后未知区域，
车辆通过 1.6 m 门洞后推进到 `(2.857, 0.264)`，距目标约 **0.300 m**，最大线速度 **0.10 m/s**，未出现倒车或几何车身碰墙。
该闭环检查在进入 0.30 m 检查范围时结束，未用它证明最终 0.25 m 停车容差或实车跟踪精度。
没有运行真实电机、真实雷达或实车动力学测试。
