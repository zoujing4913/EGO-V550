# V550：只使用 ego_ground_ws

现在打开 `/home/zoujing/ego_ground_ws` 就能看到 EGO、仿真、实车接口及本次使用的厂家源码。
无需再打开、复制或 source 外面的 `/home/zoujing/wheeltec` 工作空间。
原来的厂家目录保持不动；源码迁入清单见 [wheeltec_vendor](wheeltec_vendor/README.md)。

```text
ego_ground_ws/
├── src/ego-planner-for-ground-robot/
│   ├── ego-planner/           # 规划、地图、MPC、Patchwork
│   ├── ego_ground_sim/        # Gazebo 仿真、场景、轨迹显示
│   ├── ego_wheeltec/          # 实车传感器桥接、保护、部署入口
│   ├── wheeltec_vendor/      # 七个厂家 ROS 包及 V550 模型
│   └── tools/v550/           # 本工作空间的构建工具
├── build/                    # 在目标电脑本地生成
├── install/                  # 在目标电脑本地生成
└── log/
```

## 1. 一次性安装系统依赖

源码已经在工程内，Ubuntu/ROS 系统库仍需安装。以下命令在实际要编译的电脑上执行：

```bash
source /opt/ros/humble/setup.bash
sudo apt update
sudo apt install python3-colcon-common-extensions python3-rosdep \
  libpcap-dev libyaml-cpp-dev libboost-thread-dev \
  ros-humble-robot-localization ros-humble-turtlesim \
  ros-humble-nav2-msgs ros-humble-ackermann-msgs \
  ros-humble-robot-state-publisher ros-humble-joint-state-publisher ros-humble-xacro
```

`libpcap-dev` 是雷达驱动的编译依赖，`robot_localization` 提供融合里程计的 EKF。
二者不是外部 Wheeltec 工作空间，仍由 Ubuntu/ROS 软件包提供。
本次开发电脑缺少这两项且没有免密码 sudo，因此编译验证使用了临时解压的官方开发文件；
常规编译和真实运行请执行上面的系统安装命令。没有宣称已经在车上验证。

首次使用 rosdep，如果尚未初始化，先运行一次 `sudo rosdep init`；已有配置不要重复初始化。

```bash
rosdep update
cd ~/ego_ground_ws
rosdep install --from-paths \
  src/ego-planner-for-ground-robot/ego-planner/planner \
  src/ego-planner-for-ground-robot/ego-planner/patchwork \
  src/ego-planner-for-ground-robot/ego_wheeltec \
  src/ego-planner-for-ground-robot/wheeltec_vendor --ignore-src -r -y
```

若需要 Gazebo 仿真，也应安装 `ego_ground_sim` 对应的 Gazebo ROS 系统依赖。
实车只构建 `ego_wheeltec` 依赖闭包时不要求 Gazebo。

## 2. 编译

新开终端，仅加载 Humble，不要加载旧厂家工作空间：

```bash
source /opt/ros/humble/setup.bash
cd ~/ego_ground_ws

# 实车程序及所需的七个厂家包
colcon build --packages-up-to ego_wheeltec --parallel-workers 2 \
  --cmake-args -DCMAKE_BUILD_TYPE=Release

# 也需要仿真时，使用下面这一条，构建仿真及其依赖
colcon build --packages-up-to ego_ground_sim --parallel-workers 2 \
  --cmake-args -DCMAKE_BUILD_TYPE=Release

source install/local_setup.bash
```

两条构建命令按需要选择，不必每次都运行。内存不足时把并行数改为 1。
也可以使用工程提供的脚本，`real` 选择实车，`sim` 选择仿真：

```bash
bash src/ego-planner-for-ground-robot/tools/v550/build_workspace.sh real
```

VS Code 打开 `ego_ground_ws` 后可使用“终端 → 运行任务”，选择对应构建任务。

## 3. 以后每个终端只加载这两个环境

```bash
source /opt/ros/humble/setup.bash
source ~/ego_ground_ws/install/local_setup.bash
```

检查厂家包也来自本工作空间：

```bash
ros2 pkg prefix turn_on_wheeltec_robot
ros2 pkg prefix wheeltec_robot_urdf
ros2 pkg prefix lslidar_driver
```

预期都是 `~/ego_ground_ws/install/...`，不应指向外面的厂家工作空间。

## 4. 仿真启动方式不变

```bash
ros2 launch ego_ground_sim sim_v550_rooms.launch.py
```

仍使用 V550 麦轮模型、大房间场地和现有障碍布置。不要在同一 ROS 域内同时运行同名实车驱动。

## 5. 实车可以从同一个工作空间启动

在车上确认系统依赖、两个串口和权限，且没有重复运行厂家驱动后：

```bash
ros2 launch ego_wheeltec v550_mec_2d.launch.py \
  start_base:=true start_lidar:=true \
  lidar_type:=ls_N10Plus_uart \
  controller_port:=/dev/wheeltec_controller \
  lidar_port:=/dev/wheeltec_lidar \
  planner_config:=$HOME/ego_ground_ws/src/ego-planner-for-ground-robot/ego_wheeltec/config/ego_v550_forward_only.yaml
```

默认 `drive:=false`，只观察，不连接底盘运动输出。这个命令不自动使能车辆。
没有对应别名时，把两个端口替换为车上实际串口；不要把底盘和雷达端口接反。
IMU 默认使用厂家 `stm32` 模式，车上若使用外置 IMU，应核对硬件并另行准备相应驱动。
此命令需要真实串口，不是开发电脑上的仿真命令。

也可以把底盘和雷达单独启动以便排查问题：

```bash
# 终端 A
ros2 launch turn_on_wheeltec_robot turn_on_wheeltec_robot.launch.py \
  car_mode:=V550_mec controller_port:=/dev/wheeltec_controller

# 终端 B
ros2 launch turn_on_wheeltec_robot wheeltec_lidar.launch.py \
  lidar_type:=ls_N10Plus_uart lidar_port:=/dev/wheeltec_lidar
```

分开启动后，EGO 保持 `start_base:=false start_lidar:=false`，避免重复启动驱动。
上车只读检查、尺寸标定和低速执行步骤仍按 [V550 实车部署](V550实车部署.md) 进行。

## 6. 把工程带到另一台电脑

复制整个 `ego_ground_ws/src`，或使用本次提供的 `ego_v550_unknown_nav_20261016` 源码压缩包，
在目标电脑重新安装系统依赖并编译。该压缩包包含 `wheeltec_vendor`，以前的压缩包不包含本次迁入。
压缩包顶层是 `ego_ground_ws/`，在目标电脑用 `tar -xzf <压缩包路径> -C ~` 解压，
同时得到源码、VS Code 任务和当前 `my_maps/` 自定义地图。已有同名工程请先备份。
不要把开发电脑的 `build`、`install` 当作 ARM 车载电脑可直接运行的文件。
