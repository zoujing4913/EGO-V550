# V550 大型室内场地：房间、门和激光扫描

本入口使用厂家 V550_mec 模型、单线二维激光雷达、EGO-Planner 和 MPC。
场地从原来的 12 × 10 米扩大为 **24 × 18 米**，包含六个房间、约 4 米宽的中央走廊、
六组门框和打开的门扇，以及 **30 个柜体、桌体、箱子和圆柱障碍物**。
墙、门和家具都有对应的碰撞几何体，全部使用本地模型，不需要联网下载。

已加入膨胀区虚拟排斥脱困，V550 仿真默认只向前行驶；后方目标会先转身。
黄色箭头、保护范围和参数见 [膨胀区脱困说明](V550膨胀区脱困.md)。

## 启动

先在原仿真终端按 `Ctrl+C` 关闭旧仿真，再打开新终端：

```bash
cd ~/ego_ground_ws
source /opt/ros/humble/setup.bash
source install/local_setup.bash
export ROS_DOMAIN_ID=218 ROS_LOCALHOST_ONLY=1
export GAZEBO_MASTER_URI=http://127.0.0.1:11358
ros2 launch ego_ground_sim sim_v550_rooms.launch.py
```

默认起点是 `(-10, 0)`，位于走廊西侧空地，车头朝向 X 正方向。
Gazebo 默认固定俯视整个建筑，RViz 默认跟随车身俯视局部地图。
Gazebo 中可以用滚轮缩放；如果整栋建筑显示不全，可在同样环境的终端重新定位：

```bash
python3 install/ego_ground_sim/share/ego_ground_sim/scripts/focus_v550.py \
  --view top --height 36 --center-x 0 --center-y 0
```

## 门和障碍物

六个门口在 `(X, Y) = (-8, ±2)、(0, ±2)、(8, ±2)` 附近。
门口实际可用宽度约 1.8 米，门扇固定在打开的位置；本版本没有开门动画或自动开门控制。
门上方的横梁不会封住激光扫描高度处的通道。

先在 RViz 使用 **2D Goal Pose** 设置走廊目标，例如 `(-4.8, 0)`，观察绕过圆柱。
然后可试 `(-8, 4.2)`，让车进入左上方房间。
想进入其他房间时，先沿走廊移动到门前，再设置房内目标。
不要把目标点放到墙、柜子或蓝色膨胀障碍区域里。
EGO 仍然使用局部感知地图，不能保证一次远距离点选就能找到所有多拐弯路线。

你仍可在 Gazebo 中暂停后添加、平移或旋转方块和圆柱。
修改完使用 **File → Save World As** 保存自己的 `.world`，例如：

```text
/home/zoujing/ego_ground_ws/my_maps/my_rooms.world
```

重新加载：

```bash
ros2 launch ego_ground_sim sim_v550_rooms.launch.py \
  world:=/home/zoujing/ego_ground_ws/my_maps/my_rooms.world
```

也可以直接保存正在运行的场景：

```bash
python3 install/ego_ground_sim/share/ego_ground_sim/scripts/save_v550_world.py \
  ~/ego_ground_ws/my_maps/my_rooms.world
```

旧场地布局仍保留在 `my_maps/v550_current_scene.world`；本次撞障后另存的场景为
`my_maps/v550_collision_scene.world`。
此前较密的室内布局保留在 `my_maps/v550_rooms_current.world` 和
`my_maps/v550_rooms_before_escape.world`。当前 30 障碍版本使用源码中的 `v550_rooms.world`。

## Gazebo 中的蓝色激光

已开启传感器的 `<visualize>true</visualize>`，显示由模拟测距结果形成的蓝色射线。
射线遇到墙体和家具后截断，门洞允许部分射线进入房间；后方障碍会被前方障碍遮挡。
这是 [Gazebo 自带的传感器显示功能](https://classic.gazebosim.org/tutorials?cat=guided_i&tut=guided_i1)。

| 参数 | 当前仿真设置 |
| --- | --- |
| 类型 | 单线二维激光，360° |
| 每圈采样 | 720 点，约 0.5° 间隔 |
| 更新频率 | 10 Hz |
| 测距范围 | 0.15～12 m；规划输入保留到 8 m |
| 距离噪声 | 高斯噪声，标准差 0.003 m |
| 坐标系 | `laser_link` |

蓝色扫描面只是可视化；规划仍然经过 `/scan → sensor_bridge → /ego/obstacles → 局部地图`。
雷达高度约在离地 0.12 米附近，无法识别没有穿过扫描平面的低矮或悬空障碍。
目前没有模拟玻璃、黑色表面反射率、运动畸变等真实雷达特性。
如需减少显示开销，可关闭射线，ROS 雷达数据仍会发布：

```bash
ros2 launch ego_ground_sim sim_v550_rooms.launch.py lidar_visualize:=false
```

## 本次撞障问题的处理

此前的速度安全节点只检查指令和里程计是否超时，没有检查障碍距离。
旧绕障检查也只报告是否到达，不能据此判断复杂场景不会碰撞。
本次做了以下修改：

1. V550 仿真增加雷达碰撞拦停：将扫描点按测量时间转换到里程计坐标系，
   根据当前里程计补偿车身运动，检查指令对应的前进、倒车、转弯轨迹及制动余量。
   使用 0.18 m 车身包络半径和 0.12 m 附加间距；雷达或里程计过期也输出零速度。
   `/v550_sim/collision_stop` 为 `true` 表示该层正在拦停。
2. 最大线速度从 0.35 降为 0.22 m/s，地图膨胀从 0.20 增为 0.35 m。
3. 跟踪位置偏差超过 0.12 m 时，从实测里程计位置重新规划，避免持续从名义轨迹点规划。
   轨迹时间结束后也检查实际位置，避免车被拦停后仍被当成已经完成。
4. 补齐碰撞检查触发重规划时的新轨迹发布，避免规划器更新了局部轨迹，MPC 却继续使用旧轨迹。

这层检查会在预测运动不安全时停车，不会强行挤过障碍。
若停住，先检查目标位置和门口通道，再重新设置可达目标。
单线雷达覆盖不到的障碍仍然无法靠该层可靠保护。
Gazebo 底盘仍是理想平面运动模型，不能替代真实麦轮动力学和实车验证。

## 验证记录

以下是 2026-10-15 较早的 28 障碍场景验证，未启用后续膨胀区脱困与只前进模式。
它们不能代替更新后配置的验证。测试在独立 ROS 域与 Gazebo 实例中运行，避免手动目标干扰结果。
新的检查脚本额外把实际路径与世界文件里的墙体、门扇和障碍几何体比对，
使用半径 0.18 m 的车身圆包络检查重叠，而不依赖规划器自己的障碍地图。

| 检查 | 结果 |
| --- | --- |
| 走廊绕障：`(-10, 0) → (-4.8, 0)` | 到达并停止；车身包络无重叠 |
| 穿门进房间：上一终点 → `(-8, 4.2)` | 到达并停止；车身包络无重叠 |
| 雷达拦停 ROS 通信检查 | 空地通行、迎面障碍拦停、雷达超时拦停、数据恢复后通行，四项通过 |
| C++ 检查 | 三项扫描保护测试、四项 MPC 测试通过 |
| 行驶中临时加入障碍 | 已触发碰撞重规划、新轨迹发布和雷达拦停；无车身重叠，但最终未到达目标，自动恢复仍不稳定 |

这些是指定路线的验证结果，不代表任意目标、任意障碍布局都已验证。
报告在工作区 `dist/v550_rooms_corridor_check.json`、`dist/v550_rooms_door_check.json` 和
`dist/v550_scan_guard_check.json`。
临时障碍检查单独记录在 `dist/v550_late_obstacle_check.json`：最终速度为零、
车身最小几何间距约 0.13 m，但距离目标约 0.52 m，因此该导航到达检查未通过。
不能把“未碰撞”写成“自动绕障导航完全通过”。

复现单条路线的检查命令（会发送一个仿真目标）：

```bash
export CYCLONEDDS_URI=file://$HOME/ego_ground_ws/install/ego_ground_sim/share/ego_ground_sim/config/cyclonedds_sim.xml
python3 install/ego_ground_sim/share/ego_ground_sim/scripts/v550_sim_check.py \
  --goal-x -4.8 --goal-y 0 --timeout 90 \
  --world src/ego-planner-for-ground-robot/ego_ground_sim/worlds/v550_rooms.world \
  --report dist/v550_rooms_corridor_check.json
```

## 修改源码中的布局

世界文件：[v550_rooms.world](ego_ground_sim/worlds/v550_rooms.world)。
启动文件：[sim_v550_rooms.launch.py](ego_ground_sim/launch/sim_v550_rooms.launch.py)。
布局生成器：[make_v550_rooms.py](ego_ground_sim/scripts/make_v550_rooms.py)。
可以直接修改世界文件中各模型的 `<pose>` 和 `<size>`，或修改生成器后重新生成。
生成命令会覆盖指定的输出文件，不要用它覆盖已经在 Gazebo 中手动修改并保存的地图：

```bash
python3 src/ego-planner-for-ground-robot/ego_ground_sim/scripts/make_v550_rooms.py \
  src/ego-planner-for-ground-robot/ego_ground_sim/worlds/v550_rooms.world
colcon build --packages-select ego_ground_sim
source install/local_setup.bash
```

空场地入口继续保留：`ros2 launch ego_ground_sim sim_v550_custom.launch.py`。
原来的保存和摆放方法见 [V550 自定义地图](V550自定义地图.md)。
